# 阅座使用指南

[返回项目首页](../README.md) · [打开阅座](https://114.55.61.254/)

## 使用条件

需要管理员分配的用户号、密码，以及本人已经绑定好的学校微信账号。没有账号时，先在 [Issue 申请](https://github.com/AMT-J/IGoLibrary/issues/new?template=account_request.yml)，留下邮箱，等待邮件。

网页固定提供 1–10 号入口，但只有管理员设置过密码的用户号才开放。灰色卡片不能登录。密码验证成功后，导入学校微信授权才算完成登录。

## 授权操作

1. 在首页点击自己的用户号并输入密码。
2. 在账户页使用二维码或微信授权按钮打开学校授权入口。
3. 在微信中完成授权，复制最后跳转到学校网页的完整地址。
4. 把完整地址粘贴到授权框，提交一次，等待成功或失败反馈。
5. 成功后检查账户名称、学校和 Cookie 到期时间是否正确。

二维码是授权入口，不是你的账号密码。授权完成后的回跳链接包含临时授权码，不能分享。

**手机上操作：** 如果浏览器不能直接跳转微信，使用页面的复制入口操作，再到微信里打开。微信授权回跳后复制完整地址，再返回原浏览器页面导入。不要只复制 `code` 后面的一段文字。

**电脑上操作：** 用手机微信扫描二维码完成授权，将回跳链接复制到电脑浏览器中导入。请通过自己的设备传递链接，避免发到群聊或公开页面。

重复导入同一链接可能失败。发生错误后先查看反馈，不要不断点击提交；需要新授权码时，重新走一次微信授权。

首次绑定之后，一个用户号对应一个学校账号。后续更新 Cookie 必须来自同一个学校账号。如果确实需要更换，联系管理员处理。

## 选择座位与建立预约

### 座位地图与候选顺序

选择场馆后，页面按学校返回的坐标绘制地图。座位之外的过道、设施和区域间距会保留，不是把座位号按数字排成列表。

空闲为绿色，占用为红色，已选为蓝色。这个状态反映读取地图时的情况，不表示到计划执行时一定仍为空闲。

支持拖动、缩放和按座位号查找。点击地图上的座位加入候选，最多 5 个。候选列表的先后顺序就是尝试顺序，可调整或移除。

例如顺序为 **187 → 183 → 184**，执行时 187 已被占，会继续尝试 183，再根据响应决定是否尝试 184。授权失效、学校禁止预约或接口状态不明时，处理方式与单纯座位被占不同，最终以执行反馈为准。

### 日期、时间与重复规则

日期、时间、场馆和重复规则都在网页自定义选择器中操作。所有时间按北京时间显示，时间可以设置到 `HH:mm:ss`。

| 重复规则 | 含义 |
| --- | --- |
| 仅这一次 | 在选定日期和时间执行一次。 |
| 每天 | 每天按设置时间执行。 |
| 周一至周五 | 工作日按设置时间执行，周末跳过。 |

**执行日期是发起预约的日期。** 当前流程申请次日座位。例如周二 22:00 的计划申请周三座位，所以“周一至周五”表示周一到周五执行，不等同于“周一到周五入馆”。请按自己学校的开放时间安排。

单次计划可以安排在未来 90 d 内。保存后在预约计划页检查计划，尤其是候选顺序、执行时间和重复规则。

### 修改、停止与删除

需要调整时，使用计划页提供的操作。先看返回结果，再确认计划当前状态。计划进入执行阶段后部分操作可能暂时不可用，避免与正在进行的抢座冲突。

关闭浏览器、退出网页会话都不会停止计划。如果不再需要某次预约，请在计划页明确停止或删除，不能靠关闭页面取消。

## 总览与执行结果

总览显示最近一次计划、授权覆盖情况和最近执行状态。授权有效并且可以覆盖最近一次执行时，显示“可覆盖”。不能覆盖时，页面结合当前 Cookie 剩余有效期计算何时之后重新登录预计能覆盖。

这个判断针对最近一次计划；重复计划后面的每一次仍要关注授权有效期。学校可能提前使授权失效，抢座前应确认账户状态正常。

执行期间网页更新暂停，结束后恢复。页面不会为了展示过程实时增加学校请求。

| 结果 | 怎么处理 |
| --- | --- |
| 成功 | 查看场馆、座位号、预约日期和耗时，按学校要求签到。 |
| 失败 | 打开详细记录，查看学校返回的原因。 |
| 结果待核实 | 尚不能确认是否成功，先到学校端查看当前预约，避免重复操作。 |
| 未记录排队位次 | 学校没有返回可确认的位次，页面不会补造一个数字。 |

排队位次按学校返回的有效结果展示，从 1 开始；显示的位次不一定代表最终预约成功的先后顺序。耗时使用 `ms`、`s` 等单位。

用户号验证和学校授权都有效、页面保持连接时，预约或维持结束后会自动展示结果。后台任务运行不要求页面一直连接。

## 维持座位开关

管理员按用户号单独控制这个功能，默认不开放。管理员允许后，你才可以在自己的账户中开启或关闭。

这是一个功能开关，开启时不要求已经抢到座位。没有符合条件的座位时，程序待命；有已成功持有、尚未签到且接近签到期限的座位时，再判断是否维持**原座**。它不使用预约计划的候选座位顺序，也不主动换到其他座位。

程序根据可读取到的学校开放时间、签到期限和冷却等规则安排操作。可设置的提前时间范围，含义是相对签到期限提前处理的时间，页面使用 `s` 表示。请留出合理余量。

维持过程会尝试提前请求原座，再处理退座与重选；学校拒绝、冷却、次数限制或其他人占座仍可能导致失败。操作完成后在“维持座位记录”查看结果和耗时。

**维持不等于签到。** 请按学校规则正常使用座位；不再需要时关闭开关，并在学校端处理当前预约。功能是否适合使用，以所在图书馆规定为准。

## 常见问题

**收到了密码，为什么还要微信授权？**

密码用于进入分配给你的服务账号，学校授权用于以本人身份访问学校预约系统，二者缺一不可。

**刷新页面后怎么又要登录？计划还在吗？**

会话凭证只在当前页面内存中，刷新后需要重新验证和导入新授权。已经成功保存的计划仍在服务器上。

**网页打不开了，计划是不是停了？**

网页可能处于维护、网络异常或防护关闭状态。关闭网页入口不会主动停止后台任务，但网络故障、学校接口异常或云厂商网络封禁仍可能影响执行。可以提交不含个人信息的 Issue 询问。

**没有收到额外通知正常吗？**

正常。阅座不向微信、邮箱等渠道发送抢座通知；有登录页面时，结束后自动显示结果。学校自身消息仍由学校发送。

**为什么不能修改抢座参数？**

服务器调优、访问限制和用户管理由管理员维护。网页显示必要参数，普通用户管理自己的计划和功能开关即可。

**可以多人共用一个用户号吗？**

不要共用。用户号绑定本人学校账号，共享密码和授权会影响计划与账号安全。

**遇到异常怎么反馈？**

在 [问题反馈](https://github.com/AMT-J/IGoLibrary/issues/new?template=bug_report.yml) 中说明手机或电脑型号、浏览器、发生时间、操作步骤和脱敏后的错误内容。不要发密码、Cookie、授权链接、学号或完整个人记录。

发现可能导致越权或信息泄漏的问题，按 [安全问题反馈方式](../SECURITY.md) 私下报告。
